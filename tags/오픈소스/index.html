AI/ML 트렌드: 에이전트 하네스는 플러그인 경계에서 운영체제가 된다

오늘 AI/ML 생태계에서 눈여겨볼 신호는 더 큰 모델이 아니라 에이전트 하네스의 기능을 플러그인 경계로 분해하려는 움직임입니다. DeepSeek AI가 공개한 DeepSeek Harness(dsh)는 “Everything is a Plugin”을 핵심 설계로 내세우고, Cordis를 기반으로 에이전트 실행 환경을 구성합니다. 저장소는 2026년 8월 13일 생성됐고 17일에도 갱신되고 있어, 단순한 장기 아이디어가 아니라 빠르게 실험되는 개발자용 실행 표면으로 볼 수 있습니다. 하네스의 경쟁력은 모델 밖으로 이동한다 에이전트 하네스는 모델에게 프롬프트를 전달하는 얇은 래퍼가 아닙니다. 세션, 도구, 이벤트, 사용자 인터페이스, 확장 기능, 상태 저장과 실패 복구가 함께 움직이는 실행 시스템입니다. 이 기능들이 하나의 거대한 코어에 묶이면 새 도구를 추가할 때마다 권한·의존성·회귀 범위가 커집니다. 반대로 플러그인 단위로 나누면 기능을 교체하거나 특정 환경에서만 활성화하기 쉬워집니다. ...

멀티모달 AI의 다음 경쟁은 모델 성능이 아니라 전환 비용이다 — Muse Glimmer와 지식 증류가 여는 로컬 에이전트

오늘의 AI/ML 흐름에서 중요한 변화는 “더 큰 모델이 곧 더 좋은 제품”이라는 단순한 경쟁 구도가 약해지고 있다는 점입니다. 8월 10일 공개된 Meta의 Muse Glimmer는 Apache 2.0 라이선스의 30B 로컬·에이전틱 멀티모달 모델로 소개됐고, Transformers·llama.cpp·vLLM 생태계가 공개 당일부터 연결됐습니다. 동시에 Multiverse Computing은 교사 모델을 학습 중 계속 탑재하지 않고 top-K logits와 fused chunked KL을 활용하는 지식 증류 방식을 제시했습니다. 두 소식은 서로 다른 문제를 다루지만 같은 방향을 가리킵니다. 하나는 이미지·문서·도구 호출을 기업 내부 GPU에서 실행할 수 있는 선택지를 넓히고, 다른 하나는 장문맥 모델을 압축·개인화하는 실험의 메모리 진입장벽을 낮춥니다. 특히 모델이 30B라는 숫자만으로 실용성을 판단해서는 안 됩니다. 실제 도입에서는 모델 가중치 크기보다 멀티모달 입력 처리 지연, tool calling 실패율, 양자화 이후의 정확도, GPU 메모리 피크, 그리고 민감한 문서가 외부 API로 전송되지 않는지가 더 직접적인 비용과 리스크가 됩니다. ...

AI/ML 트렌드: Y Combinator, 자체 운영하던 '멀티플레이어 에이전트 하네스' QM을 MIT로 오픈소스 공개

2026년 8월 4일 기준, Y Combinator 산하 소프트웨어 조직 yc-software가 사내에서 실제로 운영해오던 멀티플레이어 AI 에이전트 하네스 QM을 GitHub(yc-software/qm)에 MIT 라이선스로 공개했습니다. 저장소 설명은 “Multiplayer agent harness for work"로, TypeScript 기반이며 공개 직후부터 1만 스타·1,100+ 포크를 넘길 만큼 개발자 커뮤니티의 관심이 집중되고 있습니다. 왜 “멀티플레이어"인가 지금까지 대부분의 코딩/업무 에이전트 도구(Claude Code, Codex, Cursor 등)는 한 사람이 한 개의 에이전트 세션을 운영하는 1:1 모델을 전제로 설계되어 왔습니다. QM이 주목받는 이유는 Slack 같은 팀 커뮤니케이션 채널을 통해 여러 사람이 동시에 하나 이상의 에이전트 인스턴스를 공유·조율하는 워크플로우를 정면으로 다루기 때문입니다. 실제로 QM은 Pi, OpenCode, Codex, Claude Code 같은 기존 에이전트 하네스들을 실행 백엔드로 감싸는 오케스트레이션 레이어에 가깝습니다 — 즉 “새 모델"이 아니라 “여러 에이전트·여러 사람을 하나의 작업 공간에서 어떻게 조율할 것인가"라는 운영 문제에 대한 답입니다. ...
