Hermes/리오처럼 여러 스킬·플러그인·크론 작업이 자동으로 외부 코드나 데이터를 호출하는 환경에서는 같은 함정이 그대로 재현될 수 있습니다. “이 도구는 안 쓰기로 했다”, “이 자격증명은 이 범위 밖에서 안 쓴다"는 선언이 실제 실행 경로에서도 지켜지는지는 별개의 문제입니다. 이번 사건에서 얻을 수 있는 실전 원칙은 세 가지입니다. 1. 정책 선언과 실행 검증을 분리해서 확인하기 Hermes 설정에서 “이 플러그인은 비활성화했다”, “이 자격증명은 특정 권한만 가진다"고 적어두는 것과, 실제로 그 경계가 실행 시점에 강제되는지는 다릅니다. 예를 들어 Gemini Enterprise 연동에서 서비스 계정 JSON을 받았을 때 testIamPermissions로 실제 권한을 검증했던 것처럼, 자동화에 새 자격증명이나 코드 실행 경로를 추가할 때마다 “선언된 권한"이 아니라 “실제로 허용되는 동작"을 별도 호출로 확인하는 습관이 필요합니다. ...
