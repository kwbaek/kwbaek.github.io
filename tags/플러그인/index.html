AI/ML 트렌드: 에이전트 하네스는 플러그인 경계에서 운영체제가 된다

DeepSeek AI가 공개한 DeepSeek Harness(dsh)는 “Everything is a Plugin”을 핵심 설계로 내세우고, Cordis를 기반으로 에이전트 실행 환경을 구성합니다. 저장소는 2026년 8월 13일 생성됐고 17일에도 갱신되고 있어, 단순한 장기 아이디어가 아니라 빠르게 실험되는 개발자용 실행 표면으로 볼 수 있습니다. 하네스의 경쟁력은 모델 밖으로 이동한다 에이전트 하네스는 모델에게 프롬프트를 전달하는 얇은 래퍼가 아닙니다. 세션, 도구, 이벤트, 사용자 인터페이스, 확장 기능, 상태 저장과 실패 복구가 함께 움직이는 실행 시스템입니다. 이 기능들이 하나의 거대한 코어에 묶이면 새 도구를 추가할 때마다 권한·의존성·회귀 범위가 커집니다. 반대로 플러그인 단위로 나누면 기능을 교체하거나 특정 환경에서만 활성화하기 쉬워집니다. ...

Hermes/리오 실전 팁: 플러그인 에이전트는 권한·이벤트·롤백 카드로 운영하자

DeepSeek Harness가 “Everything is a Plugin”이라는 방향을 보여준다면, Hermes/리오를 실제 업무 자동화에 적용할 때 얻을 수 있는 교훈은 명확합니다. 플러그인이나 도구를 많이 붙이는 것보다 각 확장 기능의 경계와 완료 증거를 먼저 적는 것이 중요합니다. 기능이 하나의 코어에 있을 때는 내부 동작을 믿고 넘어가기 쉽지만, 외부 플러그인이 세션·파일·네트워크·메시지에 접근하는 순간에는 작은 운영 계약이 필요합니다. 1. 플러그인마다 다섯 줄짜리 운영 카드를 만든다 새 도구를 연결할 때 아래 항목을 짧게 기록합니다. 목적: 이 플러그인이 해결하는 한 가지 업무는 무엇인가? 입력: 어떤 파일·메시지·API 응답만 읽을 수 있는가? 허용 동작: 생성·수정·전송 중 어디까지 가능한가? 금지 동작: 실거래, 공개 게시, 서비스 재시작처럼 승인 없이는 하면 안 되는 일은 무엇인가? 완료 증거: 파일 경로, 커밋 ID, HTTP 상태, 테스트 결과 중 무엇을 남길 것인가? 이 카드는 단순한 문서가 아니라 배포 전 체크리스트입니다. 특히 자동화 작업은 “성공했다”는 자연어보다 실제 산출물과 검증 결과가 있어야 다음 단계로 넘어가도록 설계해야 합니다. ...
