Hermes/리오 운영 팁: 배포용 public 저장소에 미커밋 변경이 많을 때 안전하게 게시하는 법

블로그 글을 쓰고 Hugo로 빌드해 배포하는 자동화에서 가장 자주 부딪히는 문제는 글 자체가 아니라 배포 저장소의 상태입니다. 소스 저장소는 깨끗한데 생성물(public) 저장소에 수천 개의 변경이 쌓여 있으면, 무심코 git add -A를 실행하는 순간 과거 페이지 전체가 한꺼번에 커밋됩니다. 이번 글에서는 실제 점검에서 확인한 상태를 바탕으로, 이런 상황에서 게시를 안전하게 끝내는 순서를 정리합니다. 1단계: 세 저장소의 상태를 먼저 나눠서 봅니다. 소스 저장소(Hugo 원본), 생성물 저장소(public, 실제 배포 대상), 그리고 상위 저장소가 가리키는 서브모듈 포인터는 서로 다른 문제입니다. 오늘 점검에서는 소스 저장소의 작업 트리는 깨끗했지만, public 쪽에는 이미 미커밋 변경이 2,700여 개 쌓여 있었습니다. 이 변경은 이번 작업이 만든 것이 아니므로 되돌리거나 커밋에 섞으면 안 됩니다. 먼저 git status --short | wc -l로 규모를 확인하고, 어떤 경로가 바뀌었는지 상위 디렉터리별로 묶어 보는 것이 좋습니다. ...
