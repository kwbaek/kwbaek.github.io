AI/ML 트렌드: 에이전트 하네스는 플러그인 경계에서 운영체제가 된다

August 17, 2026

오늘 AI/ML 생태계에서 눈여겨볼 신호는 더 큰 모델이 아니라 에이전트 하네스의 기능을 플러그인 경계로 분해하려는 움직임입니다. DeepSeek AI가 공개한 DeepSeek Harness(dsh)는 “Everything is a Plugin”을 핵심 설계로 내세우고, Cordis를 기반으로 에이전트 실행 환경을 구성합니다. 저장소는 2026년 8월 13일 생성됐고 17일에도 갱신되고 있어, 단순한 장기 아이디어가 아니라 빠르게 실험되는 개발자용 실행 표면으로 볼 수 있습니다.

하네스의 경쟁력은 모델 밖으로 이동한다#

에이전트 하네스는 모델에게 프롬프트를 전달하는 얇은 래퍼가 아닙니다. 세션, 도구, 이벤트, 사용자 인터페이스, 확장 기능, 상태 저장과 실패 복구가 함께 움직이는 실행 시스템입니다. 이 기능들이 하나의 거대한 코어에 묶이면 새 도구를 추가할 때마다 권한·의존성·회귀 범위가 커집니다. 반대로 플러그인 단위로 나누면 기능을 교체하거나 특정 환경에서만 활성화하기 쉬워집니다.

그렇다고 플러그인화가 자동으로 안전을 보장하지는 않습니다. 플러그인은 곧 실행 권한의 단위이기도 합니다. 어떤 플러그인이 파일을 읽고, 네트워크에 접근하고, 다른 플러그인의 이벤트를 구독하고, 모델의 출력을 후속 작업으로 넘기는지 명시하지 않으면 모듈화가 오히려 숨은 결합을 늘릴 수 있습니다. 따라서 “모든 것이 플러그인”이라는 선언은 기능 확장성의 이야기인 동시에 권한과 관측성의 설계 문제입니다.

개발자 플랫폼은 설치가 아니라 계약을 관리해야 한다#

npx @deepseek-ai/dsh web처럼 빠르게 실행할 수 있는 진입점은 하네스 실험의 마찰을 낮춥니다. 하지만 실무 도입에서는 실행 성공보다 플러그인 계약을 먼저 고정해야 합니다. 플러그인의 입력·출력 이벤트, 버전 호환성, 필요한 권한, 외부 호출 범위, 실패 시 재시도 방식, 로그에 남겨야 할 증적을 선언형 매니페스트로 관리하는 편이 좋습니다.

평가도 모델 정확도 하나로 끝나지 않습니다. 동일한 업무를 여러 플러그인 조합으로 재생하면서 세션 복구, 도구 인자, 승인 이벤트, 부분 실패, 타임아웃, 롤백이 동일하게 동작하는지 확인해야 합니다. 특히 플러그인이 서로 다른 상태를 공유한다면 이벤트 순서와 중복 실행을 테스트하지 않을 경우, 정상 데모에서는 보이지 않는 운영 장애가 발생할 수 있습니다.

실무적 의미#

기업 AI 플랫폼팀은 에이전트 하네스를 선택할 때 모델 지원 목록보다 다음 질문을 먼저 확인할 필요가 있습니다.

  1. 플러그인마다 허용된 파일·네트워크·도구 권한을 분리할 수 있는가?
  2. 플러그인 이벤트와 모델 응답을 상관관계 ID로 추적할 수 있는가?
  3. 버전 업그레이드 때 조합별 회귀 테스트와 롤백이 가능한가?
  4. 커뮤니티 플러그인의 출처·라이선스·의존성을 검증할 수 있는가?
  5. 실패한 플러그인만 격리하고 나머지 업무를 안전하게 중단할 수 있는가?

결국 에이전트 플랫폼의 다음 경쟁력은 “얼마나 많은 기능을 기본 제공하는가”가 아니라, 기능을 얼마나 작은 계약과 검증 가능한 권한 단위로 조합할 수 있는가에 달려 있습니다.
