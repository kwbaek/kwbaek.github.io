Hermes/리오 운영 팁: 모델 은퇴 공지가 떴을 때 크론과 에이전트를 점검하는 체크리스트

2026년 10월 1일 · map[email: name:Kyungwook Baek]

2026년 9월 30일, Anthropic은 Claude Sonnet 4.5(claude-sonnet-4-5-20250929)의 API 은퇴를 공지했습니다. 공식 모델 폐기 문서 기준으로 은퇴일은 2026년 11월 30일이고, 권장 대체 모델은 claude-sonnet-5-5입니다. 아직 두 달 가까이 남아 있지만, 자동화를 운영하는 입장에서는 지금이 점검하기 가장 좋은 때입니다. 은퇴일이 지나면 해당 모델 ID를 호출하는 작업은 오류로 바뀌기 때문입니다.

Hermes/리오처럼 크론과 스킬이 여러 개 돌아가는 환경에서는 모델 ID가 한곳에만 적혀 있지 않습니다. 이번 글은 그 흩어진 의존성을 찾아 정리하는 순서를 소개합니다.

1. 어디에 모델 ID가 박혀 있는지 먼저 찾습니다#

모델 이름은 생각보다 여러 곳에 남습니다.

  • 기본 모델 설정(config.yaml의 model 항목)
  • 프로필별 설정(프로필마다 따로 둘 수 있음)
  • 크론 작업별로 지정한 모델 오버라이드
  • 위임(subagent)이나 보조 작업용으로 따로 지정한 모델
  • 스킬·레퍼런스 문서 안의 예시 명령, 스크립트 속 하드코딩된 문자열

search_files로 sonnet-4-5 같은 폐기 대상 문자열을 작업 디렉터리와 설정 디렉터리에서 한 번에 검색하면 대부분 잡힙니다. 검색 결과는 “실제로 호출하는 곳"과 “문서에 예시로 적힌 곳"으로 나눠서 보는 편이 좋습니다. 앞쪽만 바꾸면 되기 때문입니다.

2. 교체는 한 번에 하지 말고 한 건씩 검증합니다#

대체 모델이 정해졌다고 전부 한꺼번에 바꾸면, 문제가 생겼을 때 원인을 가리기 어렵습니다.

  1. 설정 한 곳을 바꿉니다.
  2. 해당 설정을 쓰는 작업 하나를 실제로 실행해 봅니다.
  3. 출력 형식(예: [SILENT] 토큰, 정해진 보고 양식)이 유지되는지 확인합니다.
  4. 문제가 없으면 다음 작업으로 넘어갑니다.

특히 형식 규약이 엄격한 크론(짧은 불릿 보고, 고정된 섹션 순서 등)은 모델이 바뀌면 문체와 길이가 달라질 수 있으니 첫 실행 결과를 눈으로 확인하는 것이 안전합니다.

3. 시간 여유를 활용해 비교 실행을 해 둡니다#

은퇴 전까지 시간이 있으니 같은 입력으로 기존 모델과 새 모델을 모두 돌려 결과를 비교해 볼 수 있습니다. 비교 항목은 단순해도 충분합니다.

  • 지정한 출력 형식을 지켰는가
  • 도구 호출 횟수와 실패율이 비슷한가
  • 실행 시간과 비용이 허용 범위 안인가

이 기록을 남겨 두면 나중에 “왜 이 모델로 바꿨는지"를 설명하기도 쉽습니다.

4. 폐기 일정을 한곳에 적어 둡니다#

폐기 공지는 한 번 읽고 잊기 쉽습니다. 공식 문서에는 모델별 폐기 일정이 표로 정리되어 있으니, 사용 중인 모델과 은퇴일만 간단히 메모해 두면 됩니다. 이번에 문서를 보면 Haiku 4.5는 현재 활성 상태이며 “2026년 10월 15일 이전에는 은퇴하지 않는다"고 되어 있습니다. 이처럼 ‘최소 이 날짜까지는 유지’라는 표현은 보장이 아니라 하한선이라는 점도 함께 기억해 두면 좋습니다.

5. 점검 체크리스트#

  • 폐기 대상 모델 ID를 설정·크론·스크립트·스킬에서 모두 검색했는가
  • 실제 호출 지점과 문서상 예시를 구분했는가
  • 대체 모델로 작업 하나씩 실행해 형식 규약을 확인했는가
  • 비교 실행 결과(형식·실패율·비용)를 간단히 기록했는가
  • 은퇴일과 대체 일정을 메모했는가

정리#

모델 은퇴는 갑작스러운 장애가 아니라 미리 공지되는 변경입니다. 공지 직후에 의존 지점을 찾아 하나씩 검증하며 옮기면 은퇴일에는 아무 일도 일어나지 않습니다. 자동화 운영에서 가장 좋은 장애는 일어나지 않은 장애입니다.
