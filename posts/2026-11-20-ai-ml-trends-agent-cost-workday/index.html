AI/ML 트렌드: 에이전트 비용은 토큰이 아니라 작업 단위로 봐야 한다 — OpenAI 연구조직 실측과 Gemini Mac 컴퓨터 사용

2026년 11월 20일 · map[email: name:Kyungwook Baek]

도입: 에이전트 청구서는 늘었는데 생산성 지표는 아직 비어 있다#

에이전트를 팀에 붙인 조직이 가장 먼저 부딪히는 질문은 “얼마나 쓰고 있나"입니다. 토큰 수나 API 호출 건수는 쉽게 집계되지만, 그것이 실제로 몇 시간치 일을 대신했는지는 잘 보이지 않습니다. 이번 주에 나온 두 발표는 이 질문을 서로 다른 방향에서 다룹니다. 하나는 OpenAI가 자사 연구조직의 에이전트 사용을 실측 수치로 공개한 보고서이고, 다른 하나는 Google이 Gemini 앱에 Mac 컴퓨터 사용 기능을 넣으면서 실행 전 승인 구조를 전면에 세운 제품 발표입니다.

핵심 신호 1: 사용량 단위가 ‘달러’에서 ‘에이전트 작업일’로 넘어간다#

OpenAI 보고서의 핵심 수치는 두 가지입니다. 첫째, API 정가 기준으로 연구자 1인당 에이전트 사용액 중앙값은 하루 약 2,400달러이고, 상위 10%(90분위)는 약 2만 3,000달러입니다. 9월 보고 때의 1,500달러, 1만 1,000달러에서 각각 62%, 105% 늘어난 값입니다. 둘째, 달러 지표만으로는 ‘벽시계 시간’이 안 보이기 때문에 보고서는 8시간의 에이전트 사용을 1 ‘에이전트 작업일’로 정의해 따로 셉니다. 연구자 1인당 작업일은 0.5에서 5.7로, 약 11배 늘었습니다. 사전학습·후학습 팀에서는 에이전트가 하루 평균 약 8작업일 돌고, 스케일링·인프라 팀은 약 4작업일입니다.

이 두 지표를 같이 봐야 하는 이유는 명확합니다. 비용만 보면 ‘비싸졌다’는 결론만 남고, 작업일만 보면 ‘얼마나 많이 맡겼는지’만 남습니다. 예산 승인은 달러로, 용량 계획은 작업일로 하는 식으로 단위를 나눠야 같은 숫자를 두고 엇갈린 판단을 피할 수 있습니다. 보고서가 월간 API 환산 지출을 연구자의 비지분 보상과 나란히 놓고 비율을 추적한 것도 같은 맥락입니다. 에이전트와 사람 사이에서 예산이 어떻게 배분되는지를 한눈에 보는 장치이기 때문입니다.

핵심 신호 2: 권한 설계가 제품 기본값이 되고 있다#

Google이 11월 19일 공개한 Gemini 앱의 Mac 컴퓨터 사용 기능은 이 흐름의 제품 쪽 사례입니다. 로컬 파일, 데스크톱 앱, 웹을 여러 단계로 조작하지만, 사용자는 앱별 권한을 고르고, 실시간 미리보기를 보고, 실행 전에 각 작업을 승인합니다. 결제·로그인·중요 작업은 승인 후에만 실행됩니다. 현재는 미국 영어 한정이며 유료 구독이 필요합니다.

중요한 것은 기능 수보다 승인 지점의 위치입니다. 에이전트가 브라우저를 넘어 데스크톱 앱까지 손을 뻗는 순간, 평가 지표 하나로는 위험을 설명할 수 없습니다. 작업 단위로 ‘어떤 앱에 접근했고, 어떤 행동 직전에 멈췄고, 누가 승인했는가’를 기록해야 합니다. 앞서 본 작업일 지표와 연결하면, 비용을 재는 단위와 권한을 재는 단위를 같은 작업 로그에서 뽑을 수 있어야 한다는 뜻입니다.

심층 분석: 기업 도입 관점에서 무엇을 가져갈 것인가#

Palo Alto Networks는 같은 시기에 오픈웨이트 모델의 후처리·추론 플랫폼 Applied Compute를 전량 주식 방식 약 45억 달러에 인수한다고 발표했습니다. 종결은 2027 회계연도 3분기 예정이며 규제 승인이 조건입니다. 보안 기업이 열린 모델을 자사 보안 정책과 묶어 주권 클라우드나 사내 환경에서 운영하겠다는 방향이 드러난 셈입니다. 에이전트가 쓰는 모델 자체가 통제 대상이 되는 흐름이라는 점에서, 앞의 두 신호와 함께 읽을 가치가 있습니다.

다만 이 수치들에는 한계가 있습니다. OpenAI 보고서의 달러 값은 API 정가 기준이라 실제 계약 단가와 다를 수 있고, 연구조직이라는 표본은 일반 기업보다 에이전트 사용 강도가 높습니다. Gemini의 Mac 기능은 미국 영어 한정이라 국내 업무 환경에 바로 적용하기 어렵습니다. 따라서 수치를 목표치로 옮기기보다, 측정 단위와 승인 지점을 먼저 정의하는 용도로 쓰는 것이 안전합니다.

실무 관점: 바로 적용할 수 있는 점검 항목#

  • 에이전트 사용량을 토큰과 달러 외에 ‘작업일’로도 기록하고, 팀별로 같은 정의를 쓰세요.
  • 컴퓨터 사용형 에이전트는 앱 접근 권한, 실행 전 승인 지점, 승인자 기록을 한 로그에 남기세요.
  • 결제·로그인·외부 발송처럼 되돌리기 어려운 행동은 기본값을 승인 필수로 두세요.
  • 제품 발표의 “안전 기능"은 지역·요금제 제약을 함께 확인한 뒤 도입 계획에 넣으세요.

결론#

에이전트 도입의 성패는 얼마나 싸게 쓰느냐보다, 무엇을 몇 작업일 맡기고 어디서 멈추게 했는지를 얼마나 정확히 재느냐에 달려 있습니다.
