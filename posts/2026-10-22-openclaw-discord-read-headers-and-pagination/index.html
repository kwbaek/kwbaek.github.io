OpenClaw/Hermes 운영 팁: cron에서 Discord 채널을 읽을 때는 봇 토큰보다 헤더와 페이지네이션을 먼저 확인하라

2026년 10월 22일 · map[email: name:Kyungwook Baek]

자동 실행 작업에서 Discord 채널 기록을 읽어야 할 때가 있습니다. 예를 들어 트렌드 스캐너가 같은 채널의 기존 게시물을 확인해 중복을 거르는 경우입니다. 이때 “채널 읽기 권한이 없다"는 결론을 내리기 전에 확인할 순서가 있습니다. 오늘 실제로 같은 증상을 겪고 정리한 내용입니다.

1. 토큰이 있다고 바로 성공하지 않는다#

Hermes 환경 파일에 봇 토큰이 있어도 요청이 실패할 수 있습니다. 먼저 HTTP 상태 코드를 분리해서 봐야 합니다.

  • 401이면 토큰 자체가 잘못됐거나 만료된 경우입니다.
  • 403이면 토큰은 유효하지만 해당 채널 권한이 없는 경우입니다.
  • 404나 빈 응답이면 채널 ID나 API 경로를 다시 확인해야 합니다.

403을 바로 “읽기 불가"로 단정하면 안 됩니다. 실제로는 요청 헤더 문제로 막힌 경우도 있었습니다.

2. User-Agent 헤더를 넣는다#

Discord REST API 호출 시 일부 환경에서는 User-Agent가 없는 요청이 차단됩니다. 봇 요청임을 식별할 수 있는 값을 함께 보내면 같은 엔드포인트가 정상 응답을 주는 경우가 있습니다. 토큰 값과 함께 헤더 값도 로그에 그대로 남기지 않는 것이 좋습니다.

3. 한 번에 100개만 읽고 끝내지 않는다#

메시지 목록은 기본적으로 최신순으로 옵니다. 하루치 기록을 확인하려면 limit을 지정하고, 마지막 메시지 ID를 before 파라미터로 넘겨 이전 페이지를 이어 읽어야 합니다. 특히 봇이 10분마다 글을 올리는 채널에서는 100개가 금방 지나가므로, 오늘 날짜 필터를 적용하기 전에 페이지가 날짜 경계를 넘었는지 확인해야 합니다.

4. 읽은 결과는 날짜와 ID로 검증한다#

수집이 끝나면 다음 세 가지를 확인합니다.

  • 기대한 날짜 범위의 메시지가 실제로 포함됐는지
  • 같은 메시지 ID가 중복되지 않았는지
  • 본문이 비어 있는 임베드·첨부 메시지를 텍스트 항목으로 잘못 세지 않았는지

이 검증을 건너뛰면 “오늘 메시지가 없다"와 “API 호출이 잘못됐다"를 구분하지 못합니다.

오늘 점검에서는 User-Agent를 넣은 요청으로 최근 100개 메시지가 정상 조회됐고, 그중 당일 날짜 메시지를 골라낼 수 있었습니다. 페이지를 더 넘겨 읽는 경우에는 위 기준을 그대로 적용하는 것이 안전합니다.

정리#

  • 채널 읽기 실패는 권한 문제와 요청 형식 문제를 분리해서 진단하세요.
  • 403 한 번으로 불가 판정을 내리지 말고, 헤더와 엔드포인트를 바꿔 재확인하세요.
  • 페이지네이션과 날짜 경계를 확인한 뒤에만 “오늘 기록 없음"을 결론으로 쓰세요.
