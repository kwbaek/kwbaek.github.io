AI/ML 트렌드: 'ZDR 설정'은 계약서가 아니라 실제 요청 경로로 확인해야 한다 — OpenRouter 제공사 퇴출과 AI 에이전트의 자율 익스플로잇

2026년 11월 22일 · map[email: name:Kyungwook Baek]

도입: 보존하지 않는다는 문장이 실제로 지켜지고 있는가#

기업이 외부 모델 API를 쓸 때 가장 많이 믿는 문장은 “데이터를 보관하지 않는다(Zero Data Retention, ZDR)“입니다. 계약서와 설정 화면에 적혀 있으니 대개 그대로 믿고 넘어갑니다. 그런데 오늘 나온 두 건은 이 믿음이 생각보다 얕다는 것을 보여 줍니다. 하나는 추론 라우터가 실제로 요청을 어디로 보내는지 외부 테스트로 드러난 사례이고, 다른 하나는 공격자 쪽 AI 에이전트가 사람이 개입하지 않은 채 취약점을 찾아 익스플로잇까지 끝낸 사례입니다. 둘 다 “신뢰 경계가 문서에 적혀 있는가"보다 “요청과 실행이 실제로 어디를 지나가는가"가 중요하다는 쪽을 가리킵니다.

1. 추론 라우터에서 확인된 문제#

OpenRouter는 2026년 11월 공지에서, Dragos의 테스트 결과를 받아 세 개 추론 제공사를 플랫폼에서 내보냈다고 밝혔습니다. 공지에 따르면 이 과정에서 125개 엔드포인트의 ZDR 자격을 취소했고, 일부는 조사 대상으로 지목된 곳이 아니라 예방 조치로 함께 뺐습니다. 복원은 검증이 끝나야 가능합니다.

중요한 부분은 공지 문구입니다. OpenRouter는 이번 결과가 OpenRouter 자체의 침해나 무단 접근을 보여 주지는 않았다고 적었습니다. 문제는 개별 제공사의 처리 경로에 있었다는 뜻입니다. 공지는 요청과 응답이 제3자로 전달되는 네트워크 경로를 기술적으로 검증하고 있다고도 밝혔습니다. 제공사별 보안 공지 목록도 함께 열려 있는데, 제공사가 보낸 공지와 외부 보고서의 주장은 아직 독립적으로 완결된 검증이 아니라는 점을 같이 봐야 합니다.

실무적으로는 두 가지가 남습니다. 첫째, 라우터를 거치는 호출은 “ZDR 엔드포인트로 가도록 설정했다"는 사실만으로 충분하지 않습니다. 둘째, 라우터의 허용 목록은 시간이 지나면 바뀝니다. 어제 ZDR 대상이던 엔드포인트가 오늘은 아닐 수 있습니다.

2. 같은 주에 나온 자율 익스플로잇 사례#

Amazon 위협 인텔리전스는 중국 연계 공격자가 AI 에이전트를 써서 의료 영상 오픈소스 애플리케이션의 경로 탐색(path traversal) 취약점을 찾고 악용한 사례를 1차 출처 블로그로 공개했습니다. 보고서에 따르면 에이전트는 프레임워크를 파악하고 API 엔드포인트를 매핑한 뒤, 파일명 파라미터가 취약하다는 것을 확인했습니다. 그리고 약 11분 만에 임의 파일 쓰기 단계까지 도달했습니다. 이후 세션에서는 같은 취약점으로 리버스 셸 페이로드를 자동 실행되는 Python 파일 위치에 심기도 했습니다.

발견 시점에 이 취약점은 어떤 보안 권고나 공개 이슈와도 연결되지 않은 제로데이였고, 패치는 없었습니다. 이 사례에서 눈여겨볼 점은 AI가 취약점을 “알려 주는” 수준을 넘어 탐색, 검증, 악용을 한 흐름으로 묶었다는 것입니다. 방어하는 쪽도 파일 업로드 경로와 파일명 처리 같은 기본 지점을 먼저 점검해야 하는 이유입니다.

3. 공통 분모: 신뢰는 문서가 아니라 경로에 있다#

두 사례는 주제가 다르지만 같은 질문으로 모입니다. 우리 시스템이 믿고 있는 경계가 실제 실행 경로와 일치하는가입니다.

  • 추론 호출의 경우, 경계는 계약 문구가 아니라 요청이 실제로 거치는 라우터, 제공사, 엔드포인트입니다.
  • 에이전트의 경우, 경계는 권한 설정이 아니라 도구 호출이 실제로 일으키는 파일 쓰기, 네트워크 요청, 명령 실행입니다.

따라서 이번 주 키워드는 “정책 확인"보다 “경로 확인"에 가깝습니다. 설정을 한 번 맞춰 두는 것으로 끝나지 않고, 주기적으로 실제 호출 결과를 측정하고 기록해야 합니다.

독자가 가져갈 점검 포인트#

  • 외부 추론 라우터를 쓰는 서비스는 민감도가 높은 요청을 ZDR 허용 엔드포인트로만 제한하는지 확인합니다.
  • 설정 화면의 값만 보지 말고, 제공사 공지와 라우터 변경 이력을 주기적으로 대조합니다.
  • 에이전트에 파일 업로드나 파일 쓰기 권한을 줄 때는 경로 검증과 쓰기 범위를 먼저 정합니다.
  • 공격 사례는 발견 시점의 제로데이 여부가 중요합니다. 패치가 없으면 우회 조치와 모니터링을 우선합니다.
