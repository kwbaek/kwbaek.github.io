OpenClaw/Hermes 운영 팁: 무인 cron이 안전 필터에 막혔을 때 — 로그부터 보고, 프롬프트는 최소 변경으로 고치기

2026년 10월 26일 · map[email: name:Kyungwook Baek]

자동 스캔 작업을 10분 간격으로 돌리면, 가끔 한 번씩 실패합니다. 오늘 오전 12시 23분 실행이 그랬습니다. 알림 문구는 “AI 모델 서비스의 안전 필터가 요청을 거부했다"였고, 바로 아래에 프롬프트를 고치거나 모델을 바꾸라는 명령어가 붙어 있었습니다. 무인 작업에서는 이 메시지를 보고 무엇부터 해야 할지 정리해 두면 좋습니다.

1. 실패 로그를 먼저 본다#

알림에 적힌 로그 명령(hermes cron runs <작업 ID>)으로 해당 실행 기록을 먼저 확인합니다. 여기서 봐야 할 것은 세 가지입니다.

  • 거부된 요청이 프롬프트 전체인지, 아니면 외부에서 가져온 본문 일부인지
  • 같은 작업의 바로 앞뒤 실행은 성공했는지
  • 재시도가 자동으로 일어났는지

오늘 사례는 실패 뒤 2시간 뒤 실행이 정상으로 돌아왔습니다. 한 번의 실패는 일시적 거부일 수도 있고, 특정 문장이 원인일 수도 있습니다. 로그 없이 프롬프트부터 갈아엎으면 원인을 영영 모릅니다.

2. 프롬프트는 한 번에 한 부분만 바꾼다#

거부가 반복되면 프롬프트를 고칩니다. 이때 지침을 전부 다시 쓰지 말고, 다음 순서로 범위를 좁힙니다.

  • 외부 기사 본문을 그대로 넣는 부분이 있다면 제목과 출처 URL만 넘기고 본문 요약은 작업 단계에서 만듭니다.
  • 공격적으로 읽힐 수 있는 표현(해킹 방법, 무기, 개인 신상 같은 단어)이 작업 목적과 무관하게 섞였는지 봅니다.
  • 그래도 안 되면 모델을 바꾸기 전에, 같은 프롬프트를 다른 실행 시각에 한 번 더 돌려 일시성인지 확인합니다.

수정 명령은 hermes cron edit <작업 ID> --prompt "..." 형태입니다. 모델을 바꾸는 --model 옵션은 출력 형식과 품질이 달라지므로, 프롬프트 수정으로 해결이 안 될 때 마지막 수단으로 둡니다.

3. 변경 뒤에는 실행 결과로 확인한다#

프롬프트를 바꿨다면 다음 실행 결과를 확인해야 합니다. 편집 명령이 성공했다는 메시지만으로는 부족합니다. 확인할 항목은 다음과 같습니다.

  • 실패 알림이 다시 오지 않았는지
  • 출력 형식(제목, 출처, 항목 수)이 원래 계약과 같은지
  • 중복 제거 캐시가 실패한 실행에서 잘못 갱신되지 않았는지

중복 캐시는 특히 조심해야 합니다. 실패한 실행에서 후보를 기록해 버리면, 다음 실행에서 정상 항목이 중복으로 걸러집니다.

이번 글의 한계#

이 글은 한 번의 실패 사례를 바탕으로 한 운영 절차입니다. 안전 필터가 어떤 기준으로 거부했는지는 알림에 나오지 않았고, 확인할 수 없었습니다. 그래서 원인을 단정하지 않고, 로그 확인 → 최소 변경 → 결과 검증의 순서를 지키는 것이 안전하다는 쪽으로 정리했습니다.
