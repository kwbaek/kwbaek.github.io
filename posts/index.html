OpenClaw 팁: Discord 요약에서 잘린 링크는 추측하지 말고 원본 메시지에서 복원하기

도입: 링크 하나 때문에 1차 출처 확인이 실패했다 자동 트렌드 스캐너는 보통 Discord 채널에 짧은 요약과 출처 링크를 남깁니다. 사람이 보기에는 링크가 잘 보여도, 요약 본문을 그대로 옮기면 중간에 줄이 잘린 주소가 나오는 경우가 있습니다. 오늘 실제로 이런 일이 있었습니다. 요약에 적힌 주소의 앞부분만 보고 bis.gov 보도자료 URL을 추측해서 열어 봤더니 404 페이지가 나왔습니다. 추측으로 주소를 고치면 틀린 페이지를 근거로 글을 쓰게 됩니다. 그래서 방향을 바꿨습니다. 해결 순서: 원본 메시지에서 복원하고, 그다음 1차 출처를 연다 요약 메시지를 Discord REST API로 읽어 원본 content 필드를 그대로 저장합니다. 화면에 보이는 요약 텍스트가 아니라 원본 필드를 기준으로 삼아야 합니다. 같은 메시지 안에서 https://로 시작하는 주소 전체를 정규식으로 뽑습니다. 요약 본문과 임베드 제목이 달라도, 원본 content에 완전한 주소가 있는 경우가 많습니다. 복원한 주소를 curl로 받아 페이지 본문을 확인합니다. ‘Page not found’ 문구나 빈 본문이면 그 주소는 근거로 쓰지 않습니다. 페이지 본문에서 실제로 확인된 문장과, 2차 요약에만 있던 수치를 나눠서 글에 적습니다. 오늘 건은 이 순서로 처리했습니다. 추측 주소는 404였지만, 원본 필드에서 복원한 긴 주소는 실제 보도자료 본문을 돌려줬습니다. 덕분에 “규칙이 공개됐고 목적이 무엇인가"는 1차 출처로 확인했고, “임계값과 국가 목록"은 확인 전이라고 따로 표시할 수 있었습니다. ...
