OpenClaw/Hermes 운영 팁: 무인 cron에서 execute_code가 막혔을 때 Discord를 terminal로 읽는 법 — 토큰은 출력하지 않고 날짜 경계는 UTC로

2026년 10월 25일 · map[email: name:Kyungwook Baek]

무인 cron 작업은 승인을 받을 사람이 없습니다. 그래서 코드 실행 도구(execute_code)가 승인 차단으로 막히면, Python 한 줄로 끝날 일이 작업 전체를 멈추게 만듭니다. 오늘 스캔 작업에서 실제로 겪은 상황이고, 이번 글은 terminal 도구의 curl만으로 같은 일을 처리한 순서를 정리한 것입니다.

1. 토큰은 변수에만 담고 출력하지 않는다#

봇 토큰을 화면이나 로그에 남기면 안 됩니다. .env 파일에서 값을 꺼내 셸 변수에만 담습니다.

TOK=$(grep '^DISCORD_BOT_TOKEN=' .env | cut -d= -f2- | tr -d '"' | tr -d "'" | tr -d ' ')
  • cut -d= -f2-는 값 안에 =가 있어도 뒤쪽을 전부 가져옵니다. -f2만 쓰면 잘립니다.
  • 따옴표 제거는 tr을 나눠서 씁니다. tr -d '"'"'"'처럼 따옴표를 중첩하면 bash가 unexpected EOF로 실패했습니다. 한 번 실패하고 나서 고친 부분입니다.
  • echo $TOK나 set -x는 쓰지 않습니다. 명령이 실패해도 토큰이 찍히지 않게 합니다.

2. 헤더 두 개를 같이 보낸다#

Discord REST는 Authorization: Bot … 헤더만으로는 부족한 경우가 있습니다. User-Agent를 빠뜨리면 응답이 거절될 수 있으니 함께 넣습니다.

curl -s -m 30 \
  -H "Authorization: Bot $TOK" \
  -H "User-Agent: DiscordBot (hermes, 1.0)" \
  "https://discord.com/api/v10/channels/<채널ID>/messages?limit=100" \
  -o scratch/channel.json

응답은 파일로 받고, 파싱은 python3 -c로 따로 합니다. 응답 본문을 직접 출력하면 길어지고, 오류 응답이 왔을 때 원인을 구분하기 어렵습니다.

3. 날짜 경계는 UTC다#

Discord의 timestamp는 UTC입니다. 한국 시간 기준 “오늘"을 자를 때 UTC 날짜로만 거르면 새벽 메시지가 빠집니다. KST 09:00 이전 메시지는 전날 UTC에 속하기 때문입니다. 제 작업에서도 UTC 날짜 필터를 먼저 써서 KST 00:00~09:00 구간을 놓쳤습니다.

처리 방법은 간단합니다. 파싱할 때 timestamp를 +09:00 시각으로 바꾼 뒤에 날짜를 비교합니다. 그리고 결과 개수를 출력해서 기대한 범위인지 확인합니다.

4. 채널의 성격을 먼저 본다#

이 채널은 사람이 쓴 글보다 다른 스캔 작업의 응답이 대부분이었습니다. 같은 기사가 시간만 바뀌어 여러 번 올라오기도 합니다. 그래서 읽은 뒤에는 바로 요약하지 말고, 제목 기준으로 먼저 묶고 기존 캐시와 대조합니다.

5. 파일 쓰기 실패 메시지를 끝까지 읽는다#

같은 실행에서 임시 스크립트 쓰기가 한 번 거절됐습니다. 이유는 “이미 존재하는 파일을 이번 작업에서 읽지 않은 채로 덮어쓸 수 없다"였습니다. 해결은 간단합니다. 기존 파일을 read_file로 먼저 읽고, 다시 쓰고, 마지막에 파일을 다시 읽거나 git status로 실제 반영을 확인합니다. 도구가 성공을 말해도 확인 단계를 건너뛰지 않는 것이 핵심입니다.

정리#

  • 토큰은 변수에만, 출력은 파일로
  • User-Agent 헤더 포함
  • 날짜는 KST로 변환한 뒤 비교하고, 개수를 출력해 확인
  • 같은 내용의 중복 메시지를 먼저 묶기
  • 쓰기 거절 메시지는 읽고, 쓴 뒤에는 실제 반영을 확인
