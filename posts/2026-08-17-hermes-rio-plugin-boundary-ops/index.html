Hermes/리오 실전 팁: 플러그인 에이전트는 권한·이벤트·롤백 카드로 운영하자

August 17, 2026

DeepSeek Harness가 “Everything is a Plugin”이라는 방향을 보여준다면, Hermes/리오를 실제 업무 자동화에 적용할 때 얻을 수 있는 교훈은 명확합니다. 플러그인이나 도구를 많이 붙이는 것보다 각 확장 기능의 경계와 완료 증거를 먼저 적는 것이 중요합니다. 기능이 하나의 코어에 있을 때는 내부 동작을 믿고 넘어가기 쉽지만, 외부 플러그인이 세션·파일·네트워크·메시지에 접근하는 순간에는 작은 운영 계약이 필요합니다.

1. 플러그인마다 다섯 줄짜리 운영 카드를 만든다#

새 도구를 연결할 때 아래 항목을 짧게 기록합니다.

  • 목적: 이 플러그인이 해결하는 한 가지 업무는 무엇인가?
  • 입력: 어떤 파일·메시지·API 응답만 읽을 수 있는가?
  • 허용 동작: 생성·수정·전송 중 어디까지 가능한가?
  • 금지 동작: 실거래, 공개 게시, 서비스 재시작처럼 승인 없이는 하면 안 되는 일은 무엇인가?
  • 완료 증거: 파일 경로, 커밋 ID, HTTP 상태, 테스트 결과 중 무엇을 남길 것인가?

이 카드는 단순한 문서가 아니라 배포 전 체크리스트입니다. 특히 자동화 작업은 “성공했다”는 자연어보다 실제 산출물과 검증 결과가 있어야 다음 단계로 넘어가도록 설계해야 합니다.

2. 이벤트를 기능이 아니라 관측 단위로 본다#

플러그인 기반 에이전트에서는 호출 자체보다 이벤트 흐름이 더 중요합니다. 입력 수신 → 권한 판정 → 도구 실행 → 결과 검증 → 후속 작업을 하나의 상관관계 ID로 묶으면 어느 단계에서 누락·중복·재시도가 발생했는지 확인할 수 있습니다. 파일을 쓴 뒤 실제 내용과 존재 여부를 다시 읽고, 빌드 뒤 생성 HTML을 확인하고, 배포 뒤 HTTP 상태와 제목을 확인하는 식입니다.

재시도 정책도 분리해야 합니다. 네트워크 타임아웃은 제한된 재시도가 가능하지만, 잘못된 파일을 생성했거나 권한 검사가 실패한 경우에는 같은 동작을 반복하지 말고 보류해야 합니다. 오류 종류를 재시도, 보류, 승인 요청, 롤백으로 나누면 자동화가 조용히 위험을 확대하는 일을 줄일 수 있습니다.

3. 확장 기능은 작게 활성화하고 조합을 replay한다#

처음부터 모든 플러그인을 켜지 말고 하나의 대표 업무와 최소 권한으로 시작합니다. 이후 실제 업무 입력을 익명화한 고정 fixture로 재생해 세션 복구, 도구 인자, 파일 생성, 실패 복구가 예상대로 작동하는지 비교합니다. 플러그인 버전을 올릴 때는 “새 기능이 동작하는가”만 보지 말고 이전 버전의 핵심 업무가 같은 결과와 증거를 남기는지도 확인해야 합니다.

실무에서 사용할 수 있는 승격 기준은 간단합니다. 증거가 완전하면 allow, 출력은 있지만 검증이 부족하면 hold, 권한 위반이나 핵심 회귀가 있으면 rollback입니다. 이 기준은 모델이나 플러그인 공급자가 바뀌어도 유지할 수 있어 특정 구현에 덜 종속됩니다.

Hermes/리오의 자동화는 도구를 많이 연결할수록 똑똑해지는 것이 아니라, 연결된 도구가 어디까지 행동할 수 있고 언제 멈춰야 하는지가 명확할수록 신뢰할 수 있습니다. 플러그인 경계를 운영 카드와 replay 테스트로 바꾸는 것이 가장 값싼 안전장치입니다.
